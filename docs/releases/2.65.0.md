## NT Helper 2.65.0 — NT Settings editor

### Global module settings
- Added a connection-scoped NT Settings editor, opened from the cog after Plugin Manager. It is also available in Play Store builds.
- Discover the module's settings hierarchy, labels, types, ranges and flags dynamically using settings protocol v1. A live connection and recognized firmware 1.20 or newer (including candidate beta versions) are required; the firmware version alone does not establish protocol support. Offline and Demo modes do not send settings MIDI.
- Browse groups in an expandable desktop sidebar or compact group picker. Drafts and navigation survive group and layout changes on the same connection; a new connection cannot receive old drafts.
- Apply valid changes in the selected group sequentially, then read back observed values. Failed or uncertain reads retain drafts and block resending affected fields until explicit recovery. Refresh can recover against the current schema without discarding drafts.
- Confirm changes marked as restarting audio or requiring reboot, and changes to the known SysEx Device ID setting. The editor never automatically reboots the module.
- Explicitly confirmed Commit to flash and Revert to saved actions are separate from Apply. The protocol provides no durable-write acknowledgement; Revert requires Refresh afterward. No factory reset or automatic flash commit is exposed.
- Path settings remain display-only, even without a read-only flag: a supported Path write contract is not established. No local-computer folder picker is presented as an NT SD-card directory picker.
- Added keyboard tree navigation, labelled controls and stable feedback areas. Automated protocol, recovery, layout and accessibility regressions cover the editor; hardware write/readback/restore timing and durable flash persistence have not been verified by this release task.

### Release maintenance
- Hardened separate store-promotion tooling to verify exact candidates and production readback, serialize store reads, resolve the current Apple version, and run selected jobs after successful inspection.
- Required graceful Windows release-runner VM shutdown after its job, artifact uploads and cleanup finish, once idle and unneeded by other work, with powered-off/offline verification. Other platform jobs do not delay safe shutdown.

GitHub publication and successful Play internal/TestFlight upload jobs do not imply production-store promotion or App Review approval. Production promotion remains a separate operation.
