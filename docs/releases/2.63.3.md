## NT Helper 2.63.3 — File-browser reliability and interaction fixes

### File browsing
- Corrected Finder-style navigation: one shared hierarchy, exactly three cascading columns, and a sliding viewport at deeper levels. Back and breadcrumbs retain the full ancestry; sibling selections replace obsolete descendants.
- Verified rename read-back now updates names, selection, saved locations and cached ancestry coherently. Refresh generations reject superseded replies, and visible directories revalidate without full-card polling.
- Kept dialog, breadcrumbs, columns, status and action controls stationary during navigation, refresh, errors, rename and upload. Existing contents stay at full opacity until coherent replacement, avoiding transient blank/“Empty” frames; renamed descendants retain their content and scroll state while being revalidated.
- Fixed the single-click race where a focus refresh could reorder rows between pointer-down and pointer-up and open the wrong folder. Stable row identity and latest-intent navigation preserve ordinary clicks and rapid sibling changes.
- Keyboard focus indicators now follow input modality: mouse browsing and rename-dialog dismissal no longer outline an arbitrary first row. Keyboard navigation and renamed cursor/selection continuity remain available.
- Simplified the toolbar to Back, Sort and Close. Refresh and New Folder live in correctly targeted column context menus; mobile blank-space long press supports these actions. Wave Cache Troubleshooting remains in the top-level System dialog.

### Safety and feedback
- Stale, uncertain or uploading files cannot authorize unsafe Load, export, download or context mutations. Connection-owned upload leases survive browser closure and manager replacement.
- SD operations fail closed when replies cannot be attributed safely; interrupted mutations are not blindly replayed. Uploads retain the protocol's 512-byte file-data chunk limit. No automatic remount/reboot or firmware Program Change indexing behavior was introduced.
- Removed routine success and progress snackbars app-wide. Errors, exceptional warnings and invalid-action recovery remain; normal state and accessibility announcements communicate completion. Routing bus assignment retains Undo as a fixed control rather than a success snackbar.

These are corrections to existing file-browser capabilities, not a new independent-pane navigation model. Live hardware `#n`/Program Change matching is not claimed as validated by automated tests.
